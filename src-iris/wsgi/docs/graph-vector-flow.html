How graph and vector search work together.

Every question runs one embedding through two searches. The graph decides which entity you mean; that decision scopes the vector search over the text. Below: the real message flow, then the logic inside the one hop where the two searches meet.

part 2  inside one hop

knowledgeOperation.onSearch — where the searches meet.

This all happens inside the single knowledgeSearchRequest hop above. One query embedding feeds both lanes; the amber graph lane (vector match plus lexical name match) yields documents that filter the teal vector lane. The chunk search runs two ways — document-scoped and per-entity via EntityMention — then merges, so a multi-entity question keeps evidence for every named entity, not just the dominant sense.
